# APPENDIX A — PRESENTING THE SYSTEM: DOCUMENTATION & TOOLING STANDARDS

**Trady Perch Design System Bible · Appendices**
*A self-referential chapter: how the Bible itself, and any tool used to browse it, is designed.*

**Inherited From:** Chapter 59 (Documentation & Help Content Design), Master Vision §25.10 (The One-Brand Test). Design System Bible Chapter 1, in full.

---

## 1. INTRODUCTION

A design system that specifies a beautiful product and then lives inside a generic, unstyled internal wiki has quietly failed its own One-Brand Test at the one surface its own designers look at every single day. This appendix exists so that this Bible's own home — whatever internal documentation site or tool eventually hosts it — is held to the same standard it sets for everything else.

This appendix depends on Chapter 59's educational register directly and, recursively, on the entire Bible as its own subject matter.

---

## 2. PHILOSOPHY

The rejected alternative is treating internal documentation tooling as exempt from the brand standards it documents, on the theory that "it's just for the team, not for clients." This was rejected because a team's own daily tools shape how that team thinks about quality — Master Vision §25.2 already makes this argument for internal admin panels; this appendix makes it for the Bible's own presentation layer, arguably the single most-viewed internal surface of all.

---

## 3. CORE PRINCIPLES

### Pa-1 — The Bible's Own Presentation Passes the One-Brand Test

**Purpose.** Whatever tool renders this Bible for browsing — a static site, an internal wiki, a design-tool plugin — uses Chapter 3's palette, Chapter 4's typography, and Chapter 6's grid, exactly as any other product surface would.

**Reasoning.** Direct application of Master Vision §25.10: if the Trady Perch logo were removed from the Bible's own hosting site, a person familiar with the brand should still recognize it as Trady Perch's.

**When it applies.** To any tool or site presenting this Bible. **When it does not apply.** To the raw markdown source files themselves, which are production artifacts, not a presentation layer — this principle governs the rendered, browsable experience, not the authoring format.

### Pa-2 — Every Chapter Is Independently Linkable and Searchable

**Purpose.** Any chapter, and any numbered principle within it (P1, T-3, Bt-2), is directly linkable and appears in search results by its specific code, not only by chapter title.

**Reasoning.** Descends from this Bible's own citation discipline (Chapter 63) — a citation system this precise is only useful if the presentation layer actually resolves those citations to a specific, linkable location.

**When it applies.** To the Bible's presentation tooling. **When it does not apply.** No exception.
